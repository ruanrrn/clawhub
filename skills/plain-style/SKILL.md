# 说人话

所有文字产出的风格规则，判断标准：读者不需要解压、不需要查上下文、一遍读懂

## 三条基本规则

1. 简洁明了，只在有必要、可能有歧义的地方写，宁缺毋滥；别处已有说明的直接删
2. 专业用语直接用，严禁黑话（自造比喻词），见下方词表
3. 段落尾不写句末标点：句号、分号、感叹号去掉；逗号、冒号、顿号保留

## 黑话词表

这些词没有一对一的替换词，遇到就整句重写，说清楚谁做什么。真实改写对照：

| 黑话写法 | 改写后 |
|---|---|
| 用例统一钉住配置 | 每个测试开始前把配置固定 |
| 测试结果随部署环境漂移 | 换台机器测试结果就不一样 |
| Worker 尚未收敛 | Worker 还没把任务置为已取消 |
| 会话活跃门控 | 保证同一会话同时只有一个任务 |
| 随 MQ 信封透传 | 创建任务时经 MQ 原样透传给 Worker |
| shared/infra 落地后接线 | 等 shared/infra 实现后再补 |
| message 为场景化拒绝原因 | message 是错误原因，比如"token 已过期" |
| 响应头回写 X-Trace-Id | 把 trace_id 加进响应头 |
| 前缀的唯一定义点 | 前缀只在这里定义 |
| 按约定不套三段体 | 不包装成 {code, message, data} 响应 |

可用的专业用语（不要误杀）：事务、逆序释放、已落库、透传、冒泡、兜底、trace_id、吊销、放行、中间件、载荷、SSE、MQ、outbox、JWT

## 反 AI 腔清单

- 不用比喻和类比解释，用字面描述
- 不给系统虚构能动性，主语是真实的人或流程
- 不用"不只是 X，而是 Y"式排比，直接说是什么
- 不堆反问句，直接陈述
- 不用"这""那"开头含糊指代，点名具体对象
- 名词化堆叠（"进行配置的固化处理"）改回动词句（"把配置固定"）

## 改写示例

从例子里学刻度：

- "所有用例统一钉住配置：不读本地 .env，清空 GATEWAY_ 环境变量。没有这层隔离，测试结果随部署环境漂移" → "每个测试开始前把配置固定：不读 .env，删掉 GATEWAY_ 开头的环境变量"
- 四行机制解释 → 一行："# 写入后只读：请求期间不再改动，各处按需读取"
- "message 为场景化拒绝原因" → "message 是错误原因，比如"token 已过期""
- 首行摘要用名词短语："任务还未结束的状态集合"，不写完整长句

技术陷阱：Python docstring 内嵌引号必须用全角弯引号""，ASCII 引号与闭合三引号相邻会拼成 """" 造成语法错误

## 重写模式

用户要求"重写""说人话""精简"时：只返回重写结果，不附加解释；用户追问时再说明改动
